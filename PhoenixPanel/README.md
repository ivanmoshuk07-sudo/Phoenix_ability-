# PhoenixPanel 0.3.1

Плагин для ElvUI на Sirus (WoW 3.3.5a). В проекте использована логика StandaloneNames v0.10.18 с четырьмя исправлениями.

## Установка и перенос настроек

1. Скачайте `PhoenixPanel_v0.3.1.zip` из папки проекта. Распакуйте папку `PhoenixPanel` в `Interface/AddOns`. В игре должен быть включён ElvUI.
2. Если переходите со StandaloneNames, отключите его в списке модификаций, чтобы избежать дублирования панелей. Сохраните настройки ElvUI в `WTF`.
3. На первом запуске PhoenixPanel копирует настройки из текущего профиля ElvUI. Профили способностей, записи, триггеры и оформление переходят в динамическую панель. Настройки DBM и координаты рамок динамической панели и DBM тоже копируются. При первом открытии другого профиля ElvUI перенос выполняется для этого профиля отдельно.
4. Откройте настройки командой `/phoenixpanel` или через раздел PhoenixPanel в ElvUI. Расположение рамок настраивается в ElvUI через «Перенос рамок».

## Панели

- **Стационарная.** Начинается с пустого списка. Выберите тип и укажите ID способности, бафа, дебафа или предмета. Порядок задаётся кнопками «Выше» и «Ниже». КД, готовность и наличие ауры меняют состояние иконки, сохраняя её позицию.
- **Динамическая.** Очередь способностей строится по готовности и условиям триггеров. Чтобы проверить условия записи, откройте её редактор и нажмите «Проверить сейчас» в разделе «Триггеры». Для каждого активного условия показан результат, а ниже виден итог с учётом инверсии.
- **DBM.** Показывает настроенные большие таймеры. Панель можно отключить в **PhoenixPanel → DBM → Оформление → Включить панель DBM**.

Панели отслеживают состояние игры и показывают подсказки. Применение способностей выполняется обычными игровыми кнопками.

## Режимы динамической панели

Режим выбирается в **PhoenixPanel → Динамическая панель → Оформление**. Классический режим используется по умолчанию.

В **«Полосе применений»** первый слот занимает автоатака либо первый подходящий усилитель из списка с учётом триггеров и настройки замены. Для остальных позиций полоса рассчитывает прогноз по ГКД. На каждом шаге она выбирает способность с лучшим приоритетом из тех, которые восстановятся к этому моменту. Если к шагу ничего не готово, прогноз переносится на ближайшее восстановление.

Приоритет задаётся в редакторе записи от 1 до 10, где 1 — самый высокий, а значение по умолчанию — 5. При равном приоритете сохраняется порядок списка. Способность может появиться несколько раз, если известный КД позволяет применить её вновь. При нехватке ресурса иконка способности окрашивается синим и сохраняет место в прогнозе. Настроенные триггеры и правила замены продолжают действовать.

После успешного применения увеличивается до 150% и исчезает за 0,5 секунды иконка именно этой способности, где бы она ни стояла. Если в прогнозе несколько её копий, анимация срабатывает у ближайшей. **«Кол-во в ряду»** задаёт вместимость полосы вместе с первым слотом.
